# 持续任务、续接与经验沉淀

依据书稿 V1 第 9、10 章和附录 E、H。适用于：任务要暂停、换对话或交接；从上次进度继续；任务结束后决定留下什么；教师想把经验做成 Skill 或评估一个 Skill。

## 三个层次

- **项目（Project）**：跨任务仍然有效的长期背景，如单元顺序、课程长期目标、学校安全要求。
- **任务（Task）**：当前目标、材料和成果，如本次活动的场地、人数、临时安排。
- **对话**：当前这一轮协作。

普通一次性任务不需要维护状态记录。只有跨多轮、需要保留已确认决定的任务才需要 Checkpoint。

## 暂停前：写 Checkpoint

依据当前任务中已经确认的信息，写一份简短记录：当前目标、已完成、已确认且不得无理由改变的决定、当前成果文件或版本、未解决问题、下一步。保留必要的材料编号和文件位置，引用当前证据包，不复制整段历史对话。把你的建议和教师已确认的决定分开。没完成的动作不能写成完成。格式见 templates/H-checkpoint-and-reuse.md 表 H-1。

Checkpoint 说明做到哪一步，证据包说明凭什么判断，两者可以互相引用。

## 换对话后继续

1. 先核对你实际能看到哪些材料。
2. 复述本轮目标、已确认决定和证据边界。
3. 从记录的下一步继续。不继承其他任务的临时条件，不重新解释已经确认的要求。
4. 材料缺失时，只说明影响继续工作的关键缺口。不要靠交接摘要把不存在的文件或事实补出来。

## 任务结束：选择性沉淀

把本次新增的事实、决定和方法候选逐项分类：

| 内容 | 去向 |
|---|---|
| 本次事实、临时决定、一次异常 | 留在当前任务 |
| 同一项目后续仍有效、且已确认的背景 | 建议写入项目说明 |
| 跨任务共同遵守的原则 | 共同规则候选 |
| 一类任务反复有效的专业方法 | Skill 候选，继续验证 |
| 较长的知识、案例、量规、模板 | 参考文件或模板 |
| 确定性操作 | 脚本或固定流程 |
| 实时数据和外部动作 | 工具或系统连接 |

写明每项的理由和验证依据。不确定时留在较低层级。一次成功不自动改写 Skill 或长期规则。最终去向由教师确认，你只提写回建议。表格见 templates/H-checkpoint-and-reuse.md 表 H-2。

## 把经验做成 Skill

先判断真正值得留下什么，不默认做 Skill。只有“一类任务反复使用、换项目仍然重要、容易遗漏、明显影响质量”的判断和约束，才适合进入 Skill。模型已经能自然完成的微步骤不必固化。

适合做 Skill 时，用 templates/E-capability-evaluation.md 梳理：适用与不适用范围、必要输入、专业主线、关键步骤、教师确认点、典型失败与纠偏、交付标准和评估方式、承载方式选择。素材最好来自同一类任务的真实运行记录：任务怎样进入、首轮在哪里跑偏、教师怎样纠偏、修正后怎样变化。

## 评估 Skill

1. **无 Skill 基线。** 用一个新的真实任务，只给基础模型材料和普通要求，记录它自然出现的偏差。
2. **三类检验。** 触发：该用时用，不该用时不用（简单润色不启动完整流程）。过程：用对材料、守住已确认决定、在高责任位置停下。成果：通过四层可用性检查。
3. **至少四种案例。** 正常案例、信息不完整案例、相邻但不该调用的案例、需要教师确认的高责任案例。
4. **按失败类型修改。** 不触发，先改名称和描述；误触发，收窄适用范围；总跳过关键判断，加明确条件；主线容易丢，把它写成必须核对的基线；结果对但流程太重，删掉琐碎步骤。只是某次任务缺材料造成的失败，不写进 Skill。每次修改后重跑旧的测试，避免修好一个、弄坏另一个。

## 工具和运行框架

Skill 提供方法，工具负责访问资料和执行动作，Agent 围绕目标推进，Harness 组织模型、工具和状态，执行环境负责文件和代码操作。这些分层不要求教师额外维护一套系统；事实边界、已确认决定和最终责任仍要保留。

示例见 examples/continuous-project.md。
