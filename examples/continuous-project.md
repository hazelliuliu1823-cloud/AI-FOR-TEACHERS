# 年度科技实践的连续任务示例

来源性质：书稿 V1 10.8节方法示例整理，不是已经执行的项目日志。

## 10.8 一个完整例子：同一年度的多次科技实践

团队把“年度校外科技实践”作为 Project，保存学校安全要求、合作流程和家长沟通原则。第一次材料科学活动作为 Task A，日期、场地、现场问题只属于本次 Task。执行过程中形成的“先区分信息状态、待确认进入内部清单、活动总结只使用实际记录”等做法，先记为 Skill 候选，不能因为一次有效就立即升级为长期方法。

第二次活动改为人工晶体主题，另建 Task B。它读取 Project 中仍然有效的长期背景，但不会继承 Task A 的场地人数和临时安排；如果 Task B 中途暂停，只需保存当前 Checkpoint。若相同的信息状态处理和发布审核方法再次有效，再把它们写入相应 Skill；若多个场景都证明“待确认事实不得写成已确认”，这条规则则可以进一步提升为全局约束。

如果这一项目运行在 Agent 环境中，Harness 可以负责读取 Project 背景和当前 Task 状态，发现家校沟通 Skill，调用必要工具，并在对外发布前停在人工批准节点；需要生成或修改文件时，再由 Environment/Sandbox 执行。技术架构变化了，但“只继承该继承的内容、只自动化适合自动化的部分、关键责任仍由人确认”的工作方法没有变化。

## 可以直接检查的三件事

1. Task B是否只继承项目中仍有效的长期背景，而没有沿用Task A的临时场地和人数。
2. 暂停记录是否能说明当前成果、已确认事项与下一步。
3. 任务结束后，哪些内容还只属于本次，哪些具备继续验证或写回的依据。
